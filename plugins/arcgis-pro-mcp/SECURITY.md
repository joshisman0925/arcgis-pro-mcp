# 安全邊界與問題回報

安裝前及首次查詢資料前，請先了解以下範圍：

- **本機執行不代表資料不會離開電腦。** MCP 工具結果交給 AI 客戶端，可能再送往模型服務。結果可能包含專案／資料來源路徑、圖層名稱、欄位、屬性、座標及編輯前後值。是否保存、訓練或轉送由客戶端與模型服務的政策決定。
- **依資料權限選擇查詢範圍。** 查詢時明確指定必要欄位、條件與筆數；未指定欄位時可能讀取最多 50 個非幾何欄位。不要將機密 GIS 資料交給未獲組織核准的客戶端／模型服務。圖層屬性與服務訊息是資料，不是授權操作或變更安全規則的指令。
- **Named Pipe 的信任範圍是同一 Windows 帳號。** 通道不開網路監聽埠，但同帳號的其他程式也可能呼叫 Add-in；沒有獨立的應用程式身分驗證。工具白名單與參數驗證不能隔離已取得同帳號權限的惡意程式。
- **確認參數不是人員授權。** `confirm=true` 等參數用來避免漏填操作意圖，不能取代 AI 客戶端的工具權限與使用者同意。修改只應依使用者要求執行。
- **儲存有整體範圍。** `save_edits` 會儲存所有待存資料編輯，包含人工編輯；`save_project` 儲存整份 APRX 設定。不要把它們當成「只儲存上一個 MCP 操作」。地理處理與匯出檔可能立即寫入磁碟，逾時／取消不保證回復。
- **遠端圖層仍會使用原有服務。** ArcGIS Pro 存取遠端資料時，可能聯絡已設定的 GIS 服務。本套件不代管這些服務或授權。
- **報告與備份也可能含資訊。** 本機 `validation-*.json` 可能包含專案路徑與樣本屬性；不要公開上傳。安裝備份與匯出資料需要由使用者依政策保管及清理。

隱私處理細節見 [PRIVACY.md](PRIVACY.md)。本專案不提供任意 Python、C# 或 SQL 執行，也不宣稱消除客戶端、作業系統或 GIS 服務的風險。

## 工具的外部存取宣告

MCP 的 `openWorldHint` 描述工具可能接觸的外部實體，不是傳輸是否使用本機通道。除了只列出本機程序或固定能力的 `list_sessions`、`ping`、`list_geoprocessing_tools`，其餘工具保守標示為 `true`：Pro 專案可能包含遠端服務、外部資料與不受信任的內容。這不代表每次呼叫都會連網，也不會新增網路權限。此宣告只是提示，不能取代客戶端授權、輸入驗證或組織資料政策。

定義依據：[MCP Tool Annotations](https://blog.modelcontextprotocol.io/posts/2026-03-16-tool-annotations/)（查核日期：2026-10-20）。

## 輸出路徑

`export_map`、`export_layout`、`run_geoprocessing` 的 `outputPath` 在送進 Pro 前由 MCP Server 檢查：必須是磁碟代號開頭的絕對路徑，拒絕 UNC／`\\?\` 裝置前綴、`..` 與 `.` 片段、空片段、結尾為句點或空白的片段、`: < > " | ? *` 與控制字元，以及 `CON`、`NUL`、`COM1`、`LPT1` 等保留裝置名稱。這些寫法會被 Win32 改寫，可能寫入既有檔案的替代資料流、裝置或與檢查時不同的檔案，繞過「只寫新檔」規則。Add-in 端另外拒絕既有目標並要求父資料夾已存在。

限制：對應成磁碟代號的網路磁碟機（例如 `Z:`）仍視為本機路徑；Add-in 尚未重複上述片段規則，直接呼叫 Named Pipe 的同帳號程式不受 MCP Server 檢查（見上方信任範圍）。

## 開發與合併

變更透過 PR 合併至 `main`，須通過中央 `ci-standards` 的 CI／安全 Gate，以及本專案的測試。中央流程以 `singi0771/ci-standards@v2` 更新，屬於受信任的供應鏈來源。掃描通過不等於沒有漏洞。

npm 依賴以 `package-lock.json` 鎖定，CI 一律 `npm ci --ignore-scripts`。`npm test` 先執行 `scripts/check-lockfile.mjs`：每個套件須從 `https://registry.npmjs.org/` 下載並附 sha512 integrity，拒絕 git、其他網址或 HTTP 來源，避免被改寫的 lockfile 悄悄換來源。Dependabot 更新有 7 天冷卻期。

Release Add-in 使用可重現編譯與來源路徑映射，不產生 PDB。發行前仍須掃描 DLL 與壓縮包，避免包含本機路徑、機密及測試資料。已公開的舊版本／Git 歷史不會因新版本修正而消失。

## 回報問題

不要在公開 issue 貼出密碼、token、私人路徑、GIS 樣本或可利用的完整攻擊細節。先使用 GitHub 的私人漏洞回報功能（若有啟用）；若無，先提出不含敏感資訊的聯絡請求。憑證若已外洩，應先向發行者撤銷／輪替，不能只刪除檔案。
